## 1. 分层与模块依赖

### 1.1 依赖方向（只允许自上而下，禁止反向引用）

```
L5 交互      pa.api  pa.cli  pa.console  pa.procs
               │ 只能通过 store.facades 调用核心功能（v1.1·D21）
L4 编排      pa.hub(auth,dedup,router,assess,mandate,policy,subscriptions,queue,dispatcher,pause)
             pa.ci(pipeline,risk,merge_gate,review,hooks)   pa.judge(judge,human_gate,precedents,reasons)
L3 能力      pa.skills  pa.engines(+gui)  pa.workspace  pa.sandbox  pa.tools  pa.memory  pa.notify  pa.cost
L2 外部边界  pa.scm  pa.effects(handlers)  pa.ingress  pa.secrets(providers)
L1 基础      pa.store(models,db,transitions,jsonl,archive,facades)  pa.config  pa.obs
```

### 1.2 关键约束

| 约束 | 说明 |
|---|---|
| 状态写入入口唯一 | `tasks` 和 `pull_requests` 的状态字段，只能由 `pa.store.transitions` 修改 |
| 对外写入入口唯一 | 平台、飞书、WebDAV 的写调用，只能出现在 `pa.effects.handlers.*` 中；其他模块只能调用 `effects.enqueue(...)` |
| 密钥获取入口唯一 | 只有 `pa.secrets.resolver` 能读取密钥值；其他模块只持有 `SecretRef` |
| 引擎接触不到密钥和工具实现 | 引擎只能看到 `EngineRequest`；工具需要的凭证由 `pa-core` 一侧持有（§17.3） |
| 进程间不直接通信 | 进程之间只通过 SQLite 协作（§3.3） |

### 1.3 进程与模块的对应关系

| 进程 | 加载的模块 | 单例方式 |
|---|---|---|
| `pa-server` | api、console、ingress（Webhook 和飞书长连接）、facades | — |
| `pa-core` | hub、ci、judge、notify、effects.runner、obs.health、APScheduler | 数据库锁 [实现约定：`system_state` 中 `core_lock` 行，按心跳续期] |
| `pa-worker` | skills、engines（A/B 档）、workspace、tools.mcp_server | 槽位数 = `worker.slots` + `reserved_owner_slots` |
| `pa-sandbox` | sandbox | `sandbox_slots` = 1 |
| `pa-gui` | engines.gui | `gui_slots` = 1，全局 GUI 锁 |

## 3. 关键算法

### 3.1 中台流水线（`hub.pipeline`，§6、§4.1.1）

```
def process(event):
    if not auth.verify_source(event): mark(event, "rejected"); return
    principal = auth.resolve(event.actor)                       # principals.yaml
    if dedup.is_duplicate(event): mark(event, "duplicate"); return
    if task := subscriptions.route(event):                      # D7 订阅续接
        if is_owner(principal) and event_from_human(event):
            if task.ended and not task.stopped_by_owner:
                if mandate.revalidate(task): resume(task, input=event)    # 原工作区、原分支
                else: fallthrough                                # 授权失效，当作新事件处理
            else: deliver_input(task, event)
        elif task.running: deliver_input(task, event, context_only=True)  # 机器人和 CI 的消息只作为上下文
        if handled: return
    for rule in router.ordered_rules():                          # 按 rank 升序
        if not rule.matches(event): continue
        strength = gate(event, principal, rule)                  # 明确请求 / 推断 / 不准入
        if strength is None: continue
        if strength == "inferred":
            if rule.accept_mode == "off": record_off(); 
            elif rule.assess and not assess.match(event, rule):  # D5
                pass
            elif rule.accept_mode == "observe": observations.add(would_accept=True)
            else: create_task(event, rule, mandate(strength="inferred"))
        else:                                                    # 明确请求：任何模式下都执行
            create_task(event, rule, mandate(strength="explicit"))
        if not rule.continue_: break
```

- **明确请求**的定义（§6.3）：你本人手动触发、@ 提及 PA（`addressed=True` 且发起人是 owner），或你在已订阅线程中的后续评论。规则 `require: {actor_in: [owner]}` 满足、且事件由 owner 主动发起（例如打标签）时，也视为明确请求。[实现约定，依据 §19.3 示例中的注释]
- 不在白名单的发起人：写 `events.status = observed`，不建任务（§6.1）。

### 3.2 派单领取（§6.4）

```sql
BEGIN IMMEDIATE;
UPDATE tasks SET status='leased', lease_owner=:w, lease_until=:now + :timeout + 60,
       reserved_slot=:use_reserved, version=version+1
WHERE id = (
  SELECT t.id FROM tasks t
  WHERE t.status='queued'
    AND t.skill_id IN (:runnable_skills)
    AND (t.repo IS NULL OR t.repo NOT IN (:locked_repos))
    AND (t.concurrency_key IS NULL OR t.concurrency_key NOT IN (:running_keys))
    AND (:use_reserved = 0 OR json_extract(t.mandate_json,'$.strength')='explicit')
  ORDER BY t.pinned DESC, t.priority ASC, t.manual_rank ASC NULLS LAST, t.skill_rank ASC, t.enqueued_at ASC
  LIMIT 1)
RETURNING id, skill_id, repo, retry_count, engine_hint;
COMMIT;
```

- **槽位**：普通槽位满时，`use_reserved=1`，此时只领取明确请求类任务（D9）。保留槽位不受预算熔断拦截（§15）。
- **续期**：每 30 秒执行一次 `UPDATE … SET lease_until=? WHERE id=? AND lease_owner=?`。影响行数为 0 时，立即取消引擎运行。
- **回收**：`pa-core` 定期把 `lease_until < now` 的任务改回 `queued`（不计入 retry），并标记 `runs.recovered=1`；下次执行时，提示词前加恢复说明（D2）。回收按 `enqueued_at` 从早到晚进行。
- **暂停**：`system_state.paused='1'` 时，派单器直接返回，不领取任务（D18）。

### 3.3 排序值（§6.4）

```
STEP = 1000
move(id, before=b):  prev = 位于 b 之前的那一项
    if prev is None: new = rank(b) - STEP
    elif rank(b) - rank(prev) > 1: new = (rank(prev) + rank(b)) // 2
    else: renumber_all(step=STEP); 重新执行 move
to_top: new = min(rank) - STEP ; to_bottom: new = max(rank) + STEP
```

### 3.4 引擎选择（§8.3、v1.1·K3）

```
candidates = expand(skill.engines)          # role → engines.yaml roles[role] 列表；ref 直接使用
for e in candidates:
    if e.tier not in skill.allowed_tiers: continue
    if e.tier == "C" and (skill.risk_ceiling != "low" or task.needs_code): continue
    if role == "review" and e.model_or_id == last_writer(task): continue   # 只剩同一模型时，用另一引擎并标记 same_model_fallback
    if task.retry_count > 0 and e.id == last_engine(task) and others_available: continue
    if not health_ok(e) or breaker_open(e) or not slot_free(e) or not budget.allow(e.estimate(req)): continue
    return e
```

- 优先级：同一软件同时有 A/B 档和 C 档引擎时，优先选 A/B 档（§8.2）。
- 错误处理：
  - `transient`：同一引擎退避重试 1 次；
  - `auth` / `quota` / `ui_drift`：换引擎，并计一次熔断；
  - `invalid_output`：先让引擎修正 1 次，仍失败再换引擎。

### 3.6 判断层决策（§11）

```
def judge(task, run):
    if failed(run):                                    # error 非空 / status==failed / 超时 / 格式不合规
        if run.error.kind == "transient" and transient_retries_left: retry_same(); return
        if task.retry_count < limits.max_retry: requeue(prefer_other_engine); return
        return ask_owner(reason="retry_exhausted")
    r = run.receipt
    if r.status == "dropped": close(silent=True); return
    if r.draft: treat_as_not_done()
    need = (r.confidence < gate.confidence_below or r.risk == "high" or exceeds(r.risk, skill.risk_ceiling)
            or task.retry_count >= 2 or task.fix_round >= 3 or set(r.tags) & SEVEN_TAGS
            or r.status in ("needs_human","blocked") or (tier == "C" and not skill.c_tier_auto_close))
    if not need: close(notify = rule.notify != "decision_only"); return
    p = precedents.match(r.human_action, scope=task.mandate.scope)       # K9
    if p and not (set(r.tags) & NEVER_AUTO): apply_precedent(p, reason=("precedent_applied", p.id)); return
    push_decision_card(r.human_action)                 # 同一任务的待决定事项按顺序，一次只推一个
```

- `SEVEN_TAGS` = {delete_data, stop_service, spend_money, external_message, product_direction, secret_change, permission_change}
- `NEVER_AUTO` = {delete_data, spend_money, secret_change, permission_change}

### 3.9 任务阶段（§20.3、v1.1·D10），自上而下第一条命中即生效

```sql
CREATE VIEW task_stage AS SELECT t.id,
 CASE
  WHEN EXISTS(SELECT 1 FROM effects e WHERE e.task_id=t.id AND e.status='failed' AND e.attempts>=3) THEN 'owner/delivery'
  WHEN EXISTS(SELECT 1 FROM decisions d WHERE d.task_id=t.id AND d.status='pending') THEN 'owner/answer'
  WHEN t.status='succeeded' AND EXISTS(SELECT 1 FROM pull_requests p WHERE p.task_id=t.id AND p.ci_stage NOT IN ('merged','released','verified','delivered')) THEN 'owner/review'
  WHEN t.status IN ('failed','blocked') AND NOT EXISTS(<该失败之后你没有回复过>) THEN 'owner/blocked_failed'
  WHEN t.status IN ('queued','leased') THEN 'working/queued'
  WHEN t.status IN ('closed','succeeded','judged') AND EXISTS(SELECT 1 FROM subscriptions s WHERE s.task_id=t.id AND s.closed_at IS NULL) THEN 'idle'
  ELSE 'working' END AS stage FROM tasks t;
```

[实现约定] PRD §4.2 的状态机中没有 `blocked` 状态。实现时以回执 `status=blocked` 作为判断依据，即最近一条 `runs.receipt_json.status='blocked'`，`tasks` 表不新增状态值。

### 3.10 策略版本（§6.5）

```
policy_version = "p-" + sha256(canon(rules.yaml) + canon(principals.yaml)
                 + 各规则的 accept_mode + canon(merge_policy.yaml))[:6]
```

配置变更导致版本变化时：
1. 丢弃进行中的研判，按新版本重新入队；
2. 对 `mandate.policy_version ≠ 新版本` 且受影响的任务（命中的规则被修改或停用、发起人不再在白名单、接单模式不再是 auto），投递 `policy_changed` 输入；
3. 不取消任何正在运行的任务。

## 4. 容器隔离机制（§9.1.1、v1.1·K5/K4）

| 项目 | 规定 |
|---|---|
| 运行时 | `sandbox.yaml.runtime`：apple_container（默认）、tart 或 docker |
| 挂载 | 工作区快照只读挂载到 `/work`；只有产物目录 `/out` 可写 |
| 网络 | 默认 `none`；只有 install 阶段按 `install_network_allow` 白名单开放 |
| 密钥 | 不注入任何密钥 |
| 资源 | 2 vCPU、4 GB 内存、15 分钟超时；同时只运行 1 个 |
| 生命周期 | 每次运行新建，运行结束连同容器一起销毁 |
| 审查专用配置 | `review: {network: none, secrets: none, mount: readonly}`，没有任何写入工具 |
| 调用方式 | 引擎通过 `pa sandbox run -- <cmd>` 工具执行命令；Skill 声明 `sandbox.tests: container` 时强制走容器 |
| 仍在本机运行的 | 引擎进程本身，以及 git 读写操作 |

## 5. 权限控制（§17、§20.1、v1.1·D21）

| 层 | 主体 | 能力 |
|---|---|---|
| 代码强制 | 所有调用方 | 7 类必问标签；C 档硬限制；各类上限；身份分离；`blocked_commands` 只是默认约束，不构成安全边界 |
| Facade | `OwnerFacade` | 全部能力 |
| | `AgentFacade` | 只能执行 CLI 表中标注"agent 可用"的操作；不能读取密钥；不能修改合并权限矩阵、白名单、预算、密钥配置、先例；对配置只读 |
| | `ExecutorFacade` | 写回执、`handback`、订阅 `context_only` 线程 |
| | `HubFacade` / `SettingsFacade` | 编排流程使用 / 修改配置使用 |
| 平台强制 | GitHub / Gitea | 分支保护中把 `pa/ai-review` 和 CI 设为必需检查；新提交使已有审批失效；禁止强制推送 |
| 网络 | Cloudflare Tunnel | 只暴露 `/hooks/github`、`/hooks/feishu`、`/healthz` |
| 控制台 | — | 密码 + TOTP；默认只在局域网访问；如需公网访问，必须经过 Cloudflare Access |

- `awaiting_ci` → `running`（退回修改）/ `awaiting_decision` / `succeeded` / `failed`
- `awaiting_decision` → `running` / `suspended`（超时）/ `closed`
- `failed` → `queued`（重派）/ `awaiting_decision`（超过重派上限）
- `succeeded` → `judged`
- `judged` → `closed`
- `closed` → `running`（订阅续接恢复，v1.1·D7）
