# 05 部署与运维指南

> 依据：PRD v1.1 第 22 章（部署与运维）、§9.1.1（容器）、§13.3（归档）、§16.3（健康检查）、§17（安全）。
>
> 配套文件放在 `deploy/macos/`，编程智能体在实现时，把它们复制到 PA 仓库的同名目录下：
>
> | 文件 | 用途 |
> |---|---|
> | `install.sh` | 系统依赖和 PA 安装脚本（§22.1–22.2） |
> | `launchd/com.pa.*.plist.tmpl` | 7 个进程的 launchd 模板（§3.3、§18.2） |
> | `cloudflared/config.yml.tmpl` | Tunnel 路由规则（§22.4） |
> | `containers/pa-py312.Containerfile`、`containers/pa-node22.Containerfile` | 容器基础镜像（§9.1.1、§19.1） |
> | `scripts/preflight.sh` | 部署前检查（对应 §22.1 的系统设置） |
> | `../SETUP.md` | 由 Agent 带着部署的引导骨架（v1.1·D20） |
>

## 1. 部署前清单（§22.1、§24）

**系统设置**

| 项目 | 设置 |
|---|---|
| 系统用户 | 新建普通用户 `pa`，不给管理员权限 |
| 防止自动睡眠 | 开启 |
| 断电后自动启动 | 开启 |
| 网络唤醒 | 开启 |
| 屏保不锁屏 | 只有用 C 档引擎时才设置 |
| 自动登录 / FileVault | 二选一，见 §17.6 与待填参数第 9 项 |
| 局域网 IP | 在路由器上做 DHCP 保留，固定 Mac mini 的 IP |
| 系统权限 | 给 `pa-gui` 所用的 Python 授予"辅助功能"和"屏幕录制"权限 |

**需要提前准备的外部参数（对应待填参数）**
- Gitea 地址和 Bot 账号；
- GitHub App（agent 和 merger 各一个）；
- Cloudflare 上托管的域名；
- WebDAV；
- 飞书 App ID 和你的 open_id；
- 各引擎的模型名和接口地址；
- 容器运行时选型；
- 需要做线上核实的服务的版本接口。

## 2. 安装步骤

```bash
# 2.1 系统依赖与 PA（脚本内容见 deploy/macos/install.sh）
bash deploy/macos/install.sh

# 2.2 写入密钥（§22.3，以钥匙串后端为例）
pa secret set keychain/pa/feishu_app_secret
pa secret set keychain/pa/feishu_encrypt_key
pa secret set keychain/pa/feishu_verify_token
pa secret set keychain/pa/github_webhook_secret
pa secret set keychain/pa/github_app_private_key --from-file ./app.pem && rm -P ./app.pem
pa secret set keychain/pa/gitea_bot_token
pa secret set keychain/pa/gitea_webhook_secret
pa secret set keychain/pa/ark_api_key            # 其他引擎的密钥按需添加
pa secret set keychain/pa/console_pw_hash
pa secret set keychain/pa/console_totp
pa secret check --all                             # 只校验能否读取，不输出密钥值
```

- 合并身份（merger）的凭证引用，PRD 没有给出具体路径（只写了要单独建一个 App 或 Bot）。可以参照命名风格用 `keychain/pa/github_merger_private_key` 和 `keychain/pa/gitea_merger_token`，具体以 `sources.yaml` 中的实际定义为准（见 README 歧义清单 A4）。

### 2.3 外部平台（§22.4）

**GitHub**
- 建一个 agent 用的 App，授予以下权限：Issues 读写、Pull requests 读写、Contents 读写、Checks 读、Commit statuses 读写、Actions 读写（需要 `workflow_dispatch` 时）。
- Webhook 地址填 `https://<pa.example.com>/hooks/github`，并设置签名密钥。App 只安装到需要的仓库。
- 再建一个 `pa-merger` App，只授予 Contents 写和 Pull requests 写权限。
- 目标分支开启分支保护：
  - 必需检查：`pa/ai-review` 和 CI；
  - 要求分支是最新的；
  - 新提交使已有审批失效；
  - 禁止强制推送。

**Gitea**
- Bot 账号设为仓库协作者，给写权限。
- Webhook 地址填 `http://<mac_lan_ip>:8787/hooks/gitea`，并设置签名密钥。
- 另建一个 `pa-merger` 账号，用于合并。
- 受保护分支开启"启用状态检查"，必需的状态包括 `pa/ai-review` 和 CI。

**飞书**
- 建企业自建应用，开启机器人能力。
- 事件和回调选择"长连接"模式，订阅消息事件和卡片回调。
- 发布应用版本后，把机器人加到你的私聊或专用群。

**Cloudflare**

```bash
cloudflared tunnel login
cloudflared tunnel create pa
cloudflared tunnel route dns pa <pa.example.com>
cp deploy/macos/cloudflared/config.yml.tmpl ~/.cloudflared/config.yml   # 填好 <…> 占位符
```

- 如果要从外网访问控制台，另配一个控制台用的主机名，并给它开启 Cloudflare Access。

**WebDAV**

```bash
rclone config      # 新建名为 pa-webdav 的 remote，类型选 webdav
```

**一次性容器（v1.1·K5）**

```bash
brew install container            # PRD 写法如此。如果 Homebrew 上没有这个包，按 Apple Containerization 官方方式安装；也可以改用 tart 或 colima
pa sandbox images build           # 按 deploy/macos/containers/*.Containerfile 构建 pa-py312 和 pa-node22
pa sandbox run -- python -c "print('ok')"
```

### 2.4 启动与验收（§22.5）

```bash
pa config validate
pa service install      # 生成并加载 launchd 服务（server/core/worker/gui/sandbox/cloudflared/archive）
pa service status
pa doctor               # 逐项检查：数据库、密钥、各引擎、GitHub/Gitea、飞书、Tunnel、WebDAV、GUI 权限、容器运行时
pa skill test sample-direct --input "https://example.com"
pa event emit manual.test --payload '{"skill":"sample-direct","text":"hello"}'
```

**验收清单**（对应 `06` 中的 E2E 用例）

| # | 验收项 | 用例 |
|---|---|---|
| 1 | 飞书收到结案小卡 | E2E-01 |
| 2 | 沙盒仓库的 Issue 打上 `pa:fix` 标签后，走完整个 CI 流程，然后自动合并或收到决定卡片 | E2E-05 |
| 3 | 执行 `pa pause` 后，事件照常入库但不派单 | E2E-03 |
| 4 | 在 PR 下评论"再改一下 X"，能续接原任务 | E2E-07 |
| 5 | 卡片上勾选"记为先例"后，同类问题不再推送 | E2E-08 |
| 6 | 绕过 PA 直接合并未审查的 PR，会被分支保护拦下 | E2E-09 |
| 7 | 中途杀掉 `pa-worker` 进程，重启后不会重复开 PR | E2E-10 |

## 3. 日常运维手册（§22.6）

| 频率 | 动作 | 由谁执行 | 出问题怎么办 |
|---|---|---|---|
| 每 5 分钟 | 健康检查：数据库、磁盘剩余空间是否大于 10%、各引擎、GitHub/Gitea 接口、飞书、Tunnel、WebDAV、GUI 会话 | `pa-core` 自动执行 | 同一项连续失败 3 次，控制台显示为系统问题；属于 P0 的发飞书 |
| 每小时 | 用 `VACUUM INTO` 生成快照并上传 WebDAV，本地保留 48 份 | `com.pa.archive` | 执行 `pa archive status` 查看 |
| 每天 | 日志打码、压缩后上传；清理工作区（成功的保留 24 小时，失败的保留 7 天）、过期记忆和过期订阅（14 天）；检查密钥是否该轮换；GUI 剧本试运行；发每日汇总（含当天按先例处理的事项和观察记录摘要） | 自动执行 | 剧本试运行失败时熔断该引擎，并发 P1 |
| 每周 | `pa doctor --full`；`pip-audit`；`PRAGMA optimize`；更新容器基础镜像；复核观察记录 | 自动执行，结果发飞书 | 复核观察记录后，执行 `pa rule mode <id> auto` |
| 每月 | 恢复演练 | `pa backup restore --dry-run` | 演练失败视为 P0 |
| 升级 | `pa pause` → `git pull && uv sync --frozen && pa migrate && pa service restart` → `pa resume` | 手动执行；升级前会自动做一次快照 | 出问题就恢复到升级前的快照 |

### 3.1 密钥轮换（§17.4）

| 时间点 | 提醒 |
|---|---|
| 到期前 7 天 | P2 |
| 到期当天 | P1 |
| 到期之后 | 每 3 天提醒一次 |

轮换时执行 `pa secret rotate <ref>`，写入新值，然后自动做一次连通性测试；测试通过才算轮换完成。默认轮换周期为 90 天。

### 3.2 故障恢复

| 场景 | 处理 | 依据 |
|---|---|---|
| 进程崩溃 | launchd（`KeepAlive=true`）自动拉起；租约过期的任务回到队列，再次执行时带恢复提示；对外动作按幂等键检查，不会重复执行 | §16.3、§22.6 |
| 数据库损坏 | `pa pause` → `pa backup restore <最近快照>` → `pa doctor` → `pa resume` | §22.6 |
| 整机故障 | 在新机器上执行 `install.sh` → 从 git 恢复 `~/.config/pa` → 用 rclone 从 WebDAV 拉取最近快照 → `pa backup restore` → 重新写入所有密钥（密钥不在备份中） | §22.6 |
| 飞书不可用 | 连续不可用超过 15 分钟时，改用 macOS 本地通知，并标记为待补发；恢复后自动补发 | §12.3 |
| 某个引擎被熔断 | 30 分钟冷却后自动恢复；也可以手动执行 `pa engine breaker reset <id>` | §8.5 |
| 发件箱条目失败 | `pa effect list --status failed`，然后对单条执行 `retry` 或 `drop` | §9.1.2 |
| 来源 IP 被拉黑 | 1 小时后自动解除，同时会收到一条 P0 通知 | §6.1 |
| 升级或排障 | 先执行 `pa pause`，处理完执行 `pa resume` | §22.6 |

## 4. 数据位置速查（§18.2、§13.3）

| 路径 | 内容 | 备份方式 |
|---|---|---|
| `~/.config/pa/` | 全部配置、Skill、剧本、提示词覆盖、决策台账 `precedents/*.md` | git（不含明文密钥） |
| `~/pa-data/db/pa.sqlite` | 结构化数据（WAL 模式） | 每小时快照到 WebDAV；SQLite 只放在本地盘 |
| `~/pa-data/logs/{app,sessions,engines,ci,gui}/` | 日志、JSONL 会话记录、截图 | 应用日志保留 30 天；JSONL 本地保留 90 天，每天打码后上传；截图保留 7 天，不上传 |
| `~/pa-data/{repos,workspaces,tmp}/` | 仓库镜像、任务工作区、临时文件 | 不备份 |
| 钥匙串（service = `pa`） | 密钥 | 不备份，需要手动重建 |
