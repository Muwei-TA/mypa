# 06 测试策略与用例

> 依据：PRD v1.1 的验收标准（§22.5、§23），以及 `03` 中的红线 R-01 至 R-29。
> - 每个用例都注明：依据、前置条件、步骤、期望结果。
> - 测试的类型分 N（正常流程）、X（异常流程）、B（边界条件）三种。

## 1. 测试分层

| 层 | 范围 | 工具 [实现约定] | 外部依赖 |
|---|---|---|---|
| 单元 | 纯函数和单个模块：风险评估、合并权限矩阵、排序值、阶段推导、打码、提示词组装、回执校验、策略哈希 | pytest、pytest-asyncio、hypothesis（用于排序值的性质测试） | 无 |
| 契约 | 每个 `EngineAdapter`、`ScmAdapter`、`EffectHandler`、`SecretProvider`、`SandboxRuntime` 的实现，都要通过同一套契约测试；另外各写一个假实现 | pytest 参数化 | 用假实现（§18.1） |
| 集成 | 多模块组合加真实 SQLite：中台流水线、派单与租约、effects 事务、暂停、订阅续接、判断层、CI 流水线（平台用假实现） | pytest + 临时目录中的 SQLite（WAL）+ 多进程夹具 | 假 GitHub/Gitea（用 respx 拦截 HTTP）、假飞书 |
| 端到端 | 真实部署在 Mac mini 上，连沙盒仓库和测试飞书群 | `tests/e2e/` 脚本 + `pa` CLI | GitHub 沙盒仓库、Gitea 测试仓库、飞书测试应用 |

**覆盖要求**
- R 系列红线：每一条至少有 1 个 X 类用例。
- 状态机：§4.2 中每一条合法迁移和非法迁移都要覆盖。
