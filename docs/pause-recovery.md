# 暂停后的执行结果与恢复

对应 M1-12、PRD §6.4、R-04/R-21/R-22/R-23/R-25。
升级前执行 `pa migrate`，本批新增 `0006_worker_checkpoints`。

`pa pause` 后，新派单、执行结果研判、重派及 effects 发送停止，事件继续入库。
已运行的执行尝试正常结束，包含该尝试内的一次格式修正；它的回执和已发生用量
保存下来，暂停期间不把任务结案，也不创建该结果的决定或通知。

完成执行后，run、用量和后续上下文在同一 SQLite 写事务提交到检查点。任务保持
`running`，释放引擎槽位；暂停等候期间不让普通执行租约到期重新调用模型。
检查点内容经过统一打码，保留使用过的引擎及 transient 重试计数，恢复时不清零。

`pa resume` 后优先处理检查点：已有结果直接研判，不需要重新连接模型；待重试的
尝试重新检查引擎健康及槽位，再继续执行。检查点领取有独立的 owner/租约，多个
worker 只能有一个继续处理。进程在保存结果后崩溃时，租约到期后仍优先恢复已有
结果，而非把完整执行再做一遍。模型正在执行时崩溃的普通租约恢复路径保持原样。

结案/转人工/重派与检查点清除同事务完成；写入通知失败时整体回滚，留下检查点
供下次处理。owner 已取消的任务清理检查点，不再研判。暂停与结果写入发生竞态时，
研判事务会再次核对暂停状态。原有决定到期顺延保留；暂停后暂存的结果在恢复后
才创建新决定，其到期时间从此时开始计算。

验证见 `tests/test_pause_judgement.py`：15 项行为测试，覆盖恢复不重复调用、失败/
退避/取消、研判竞态、检查点并发领取、事务回滚、槽位重查和打码。
这些是自动化验证，真实部署下 E2E-01–04 的整阶段验收仍保留在进度表中。
